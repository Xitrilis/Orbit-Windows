# Исправление запуска — Orbit 0.10

В предыдущем выданном архиве обнаружен дефект engine/libcef.dll: файл содержал 39 660 608 байт, тогда как его заголовки PE и оригинальный Playnite 10.63 требуют 238 191 616 байт. Архив ZIP при этом мог успешно распаковываться: его CRC подтверждала целостность уже неполного вложенного файла.

Это подтверждённая ошибка комплектации Orbit. Она может объяснять сообщение «System issue or corrupted Playnite install detected» на присланном фото. Само сообщение Playnite общее; без журнала с конкретного ПК нельзя исключить дополнительную причину.

В этой сборке libcef.dll восстановлена из официального дистрибутива 10.63. Все 876 включённых файлов оригинального runtime без PDB проверены по размерам и CRC исходного 7z, затем зафиксированы SHA-256 в Notices/playnite-runtime.sha256. Собственные компоненты Orbit собраны заново.

## Повторный запуск

1. Полностью закрой Orbit и его Playnite через меню трея, если они работают.
2. Распакуй весь новый ZIP в новую пустую папку с правом записи, например D:\Apps\Orbit-0.10.
3. Запусти Orbit.exe из новой папки. Старую папку пока сохрани.
4. Проверка компонентов должна закончиться перед открытием главной.

Не переносить старые DLL, EXE, папки локализации и темы поверх новой сборки. Не нужно отключать антивирус или защиту Windows.

## Данные уже настроенного Orbit

Для первого чистого запуска перенос данных не требуется. Чтобы сохранить прежнюю библиотеку, закрой обе версии, оставь резервную копию старой папки, затем скопируй только нужные пользовательские данные:

- engine/OrbitData — предпочтения Orbit, оформление, история и локальные параметры.
- engine/library — база библиотеки, если путь не менялся.
- engine/ExtensionsData — параметры интеграций.
- engine/config.json — настройки Playnite, при необходимости.

Если ранее выбирался другой путь базы, учти его отдельно. Скопированные с другого ПК учётные данные или ключи могут не расшифроваться: нужно повторно войти и настроить ключ на новом компьютере. Не передавай девушке уже авторизованную личную папку вместо чистого архива.

## Если ошибка остаётся

Запусти Orbit-Diagnostics.cmd после неудачной попытки запуска. Он вызывает проверку без запуска Playnite и создаёт Orbit-report-….zip для передачи в чат, если доступна запись. Результат сохраняется в Orbit-startup-report.txt возле Orbit.exe; если папка недоступна для записи — в локальной папке Orbit пользователя, путь покажет диалог.

Проверка размеров и SHA-256 выполняется по списку, встроенному в Orbit.exe. Она не меняет библиотеку, настройки и защиту Windows. Она выявляет отсутствующие, неполные и отличающиеся компоненты, но не проверяет драйверы и фактическую загрузку DLL системой.

Для первого разбора прикрепи созданный ZIP в чат. В него включены технические события Orbit, имена повреждённых компонентов из встроенного списка и только известные типы ошибок/компоненты/HResult из последнего фрагмента engine/playnite.log. Сам журнал Playnite и текстовый Orbit-startup-report.txt не включаются: в них могут быть личные пути и данные. Сигнатур может не хватить для точного вывода; дополнительные строки стоит выбирать после просмотра конкретной ошибки. Автоматической отправки нет. Подробности — SUPPORT.md.

## Источник и сборка

Оригинал: https://github.com/JosefNemec/Playnite/releases/tag/10.63

Файл 10.63.7z: SHA-256 9af9a0db330c97879697beac9f819c16f9f544e712261a83fa4e62a8f9a2c787.

Source/Build.ps1 собирает расширение и помощник, проверяет оригинальный runtime, формирует RuntimeFiles.sha256 и встраивает его в загрузчик. После изменений UI или DLL перед выпуском нужно пересобрать загрузчик. SHA256SUMS.txt проверяет весь готовый дистрибутив; встроенный список проверяет компоненты запуска, исключая пользовательские данные.

Реальный запуск WPF/CefSharp на Windows в этой среде не выполнялся. Компиляция, проверки целостности, тесты хранилищ и браузерные сценарии не заменяют такой прогон.
